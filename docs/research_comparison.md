# Research Comparison — Zhu et al. (2025) vs This Project

Source paper: Zhu et al., *"Multi-Target Firefighting Task Planning Strategy
for Multiple UAVs Under Dynamic Forest Fire Environment"*, Fire, 2025.
https://www.mdpi.com/2571-6255/8/2/61

This document states exactly what was **taken from the paper**, what has
been **deliberately changed**, and what is a **proposed future extension**
that is not yet implemented. Nothing below claims validated novelty — this
is a research prototype used to prepare for ConvLSTM and D* Lite
integration and for experimental work.

## What was taken from the paper

- **Multi-objective mission optimization framing.** The paper formulates
  firefighting task assignment as a multi-objective problem trading off
  suppression effectiveness against cost (time/energy/travel), solved with
  a genetic-algorithm-family multi-objective optimizer. This project keeps
  that framing: NSGA-II (`mission/optimizer/nsga2.py`) optimizes the same
  two families of objectives.
- **Per-target priority/severity weighting.** The paper's task planner does
  not treat every fire region as equally worth suppressing — the highest
  priority is not simply "physically closest." This project mirrors that:
  each `SuppressionTarget` (`mission/simulation/targets.py`) carries a
  `damage_score` (severity/predicted-damage proxy) and `priority`, and the
  damage-prevention objective (`mission/fitness/objectives.py`) sums the
  selected metric across the chosen mission, not distance.
- **Mission-selection-from-Pareto-front step.** The paper does not stop at
  a Pareto set; it selects a specific mission for execution. This project
  does the same via `mission/fitness/mission_selection.py`
  (knee/utopia-nearest selection), used by the mission-path experiment and
  the online replanner.
- **Chromosome encoding as ordered target subsets.** Candidate missions are
  encoded as permutations/subsets of suppression targets
  (`mission/optimizer/chromosome.py`), consistent with the paper's
  task-assignment representation.

## What was deliberately changed

| Paper | This project |
|---|---|
| Multiple cooperating UAVs, task allocation across the fleet | **Single UAV.** All chromosomes, objectives, and mission selection assume one vehicle. Multi-UAV allocation is out of scope for this stage. |
| Plans using currently observed / available fire and environment state | **Plans using a future wildfire-risk map.** The design target is to plan against a *predicted* future fire state from a ConvLSTM model, not only the present state (see "Not yet implemented" below). |
| The paper's own path/motion planning approach for executing assigned tasks | **NSGA-II decides WHAT to do; D* Lite decides HOW to move.** This project explicitly splits high-level mission target selection (NSGA-II) from low-level local path execution and dynamic obstacle/replanning (D* Lite). D* Lite is not part of the paper's method — it is substituted here as the local planner. |
| Target severity/priority is derived from the paper's own environment model | **Target severity is a documented synthetic placeholder.** `SuppressionTarget.damage_score` is currently generated by a synthetic scenario generator (`mission/simulation/generator.py`, `mission/simulation/targets.py`), explicitly intended to be replaced by ConvLSTM-predicted severity later. It is not derived from Zhu et al.'s environment model and does not claim to be. |

## Update: ConvLSTM is now connected (was "not yet implemented" as of the
first version of this document)

`mission/simulation/prediction_source.py` now has a real
`ConvLSTMPredictionSource` implementation (not a stub): it drives the
trained `models/convlstm/best_model.pt` checkpoint, packs its own live
simulator history into the model's input tensor, and converts the predicted
fire-probability map into `SuppressionTarget` severity/priority updates —
consumed by `OnlineReplanner` exactly like the synthetic source, no changes
needed to NSGA-II or the objectives. Verified end-to-end in
`tests/test_convlstm_nsga2_integration.py` and a live demo run showing the
selected mission genuinely changing tick-to-tick based on the model's
predictions.

**Important honesty caveat, found via a separate real-world evaluation**
(`results/convlstm_eval/`, `docs/convlstm_data_architecture_critique.md`):
this checkpoint was trained entirely on the synthetic cellular-automata
simulator and generalizes poorly to real satellite-observed fires (IoU 0.54
on a real NASA FIRMS wildfire vs. a 0.91 do-nothing persistence baseline —
worse than predicting no change at all). So "ConvLSTM → NSGA-II" is wired up
and functioning correctly as a pipeline, but the prediction quality behind
it is currently only trustworthy on synthetic data, not real fires. An
attempt to retrain on a real dataset (WildfireSpreadTS, 607 real US fire
events) is in progress but has not yet completed (see `kaggle_prepare_real_data/`).

## Update: D* Lite is now implemented (was "not yet implemented" as of the
first version of this document)

`mission/optimizer/dstar_lite.py` implements the real D* Lite algorithm
(Koenig & Likhachev 2002 — incremental grid search with `g`/`rhs` values and
a priority queue, not a simplified A* substitute), wired through
`mission/optimizer/planner_stub.py` (multi-leg mission routing) and
`mission/replanning/executor.py`'s `DStarLiteMissionExecutor` — now
`OnlineReplanner`'s default executor. Other currently-live (not-yet-
suppressed) fire targets are treated as obstacles the route must avoid;
`ReplanEvent.execution_result` carries the actual cell path and its length
vs. the straight-line distance NSGA-II used internally, and
`mission/visualization/plot_replan.py` renders both so the deviation is
visible. Verified with dedicated unit tests
(`tests/test_dstar_lite.py`: open-grid optimality, obstacle routing,
unreachable-goal detection, incremental replanning after an obstacle
changes) and an end-to-end online-replanning run.

**Design point preserved from the original plan:** NSGA-II still evaluates
candidate missions using Euclidean distance internally (running full D* Lite
per chromosome would be far too expensive across a population); D* Lite only
computes the real route for the one mission actually selected each tick.

## Update: architecture-correctness pass (P(fire) vs. damage, risk map,
genuine incremental D* Lite)

A follow-up pass fixed several conceptual/implementation issues in the
pipeline described above, without retraining or modifying the ConvLSTM
checkpoint (still synthetic-only, see caveat above):

- **P(fire) is no longer equated with expected damage.**
  `SuppressionTarget.damage_score` used to be set directly to the ConvLSTM's
  predicted fire probability. It now comes from a separate, documented
  `expected_damage_proxy = fire_probability * severity_factor * fuel_factor`
  transform (`mission.simulation.prediction_source.ExpectedDamageConfig`),
  using the driving simulator's real `potential_ros_map` and
  `vegetation_density` fields — not invented numbers, but explicitly a
  **proxy**, not a validated physical damage model. `priority` still tracks
  raw P(fire) (urgency); `damage_score` tracks the proxy (expected
  consequence) — the two are now genuinely different quantities.
  Tested in `tests/test_architecture_fixes.py::TestExpectedDamageProxy`.
- **The full predicted map is preserved, not discarded after target
  extraction.** `PredictionRiskMap` (`prediction_source.py`) carries the
  raw fire-probability grid and the derived risk grid through
  `PredictionUpdate.risk_map` → `OnlineReplanner` →
  `MissionExecutionRequest.risk_map`, available to D* Lite for optional
  risk-weighted routing without forcing NSGA-II to consume the raster.
- **D* Lite's incremental replanning is now actually exercised by the
  execution path**, not just implemented and unused. `DStarLite` gained a
  proper `update_start()` (separate `km` bookkeeping from
  `update_obstacles()`, per the real algorithm) and `update_risk()`.
  `DStarLiteSession` wraps one persistent `DStarLite` instance.
  `DStarLiteMissionExecutor` now reuses that session across replanning
  ticks — `move_to()` + `add_obstacles()`/`remove_obstacles()` on the SAME
  object — whenever the immediate next target is unchanged, and only starts
  a fresh session when the goal itself changes (a genuinely different
  planning problem D* Lite's incrementality doesn't apply to). Verified by
  tests that check **object identity** across calls (not just equal
  results) — `tests/test_architecture_fixes.py::
  TestDStarLiteSessionIncremental`, `TestExecutorGenuineIncrementalReuse`.
- **Risk-weighted traversal cost (optional).** `DStarLite` blends an
  optional `risk_weight * risk[cell]` term into edge cost; `risk_weight=0`
  (default) reproduces the original pure-distance behaviour exactly, so
  nothing changed unless explicitly opted into via
  `DStarLiteMissionExecutor(risk_weight=...)`. A documented traversal-cost
  proxy, not a physically accurate hazard model. Tested with a case that
  proves the planner takes a longer, lower-risk detour when weighted.
- **NSGA-II's surrogate cost and D* Lite's actual cost are recorded
  separately, never conflated.** `objective_travel_distance` is now
  explicitly documented as a surrogate (see its docstring in
  `mission/fitness/objectives.py`). `MissionExecutionResult` carries both
  `path_length` (actual) and `straight_line_length` (surrogate), plus a
  `deviation_ratio` property; `mission/replanning/csv_export.py` writes
  both plus `dstar_used_incremental_replan` per tick.
- **Permutation decoding confirmed (with tests) to represent a genuine
  feasible subset**, not merely a full ordering: `decode_permutation`
  already stopped early on `max_mission_targets`/`max_mission_distance`
  (this was correct before this pass — it just lacked explicit tests).
  `tests/test_architecture_fixes.py::TestPermutationDecodingIsASubset`
  proves unique IDs, order preservation, and that tight constraints
  actually produce a strict subset.

## Not yet implemented (future work, not claimed as done)

- **Multi-UAV extension.** Not attempted at this stage.
- **Real-data-trained ConvLSTM.** Current checkpoint is synthetic-only; see
  caveat above.

## What has been demonstrated so far

- NSGA-II converges on synthetic single-UAV missions with 10–50 suppression
  targets, producing a genuine Pareto front (severity-weighted damage
  prevented vs. travel distance) rather than a trivially closest-target
  solution — see `results/plots/mission_path_pareto.png` and
  `results/csv/`.
- Runtime and generations-to-convergence scale with problem size in a
  measured, reproducible way (`results/plots/runtime_vs_targets.png`,
  `results/plots/generations_to_threshold_vs_targets.png`).
- An online replanning loop exists end-to-end (`mission/replanning/`),
  now including real D* Lite local routing, that records per-tick state
  (environment, mission before/after, runtime, D* Lite path) and renders it
  as a GIF/MP4 animation (`results/online_replan/`).
- Scenario diversity beyond a single uniform scatter: clustered (multiple
  independent fire fronts) and wind-driven severity scenarios
  (`mission/experiments/scenario_diversity.py`,
  `results/plots/scenario_diversity_comparison.png`).

## Limitations

- ConvLSTM predictions driving NSGA-II are only validated on synthetic data;
  real-world prediction quality is currently poor (see caveat above).
- D* Lite treats other live targets as point obstacles at their exact grid
  cell; it does not yet model realistic obstacle geometry (e.g. fire-front
  extent/radius) or a moving/growing fire boundary.
- Wind-driven severity bias is a documented linear proxy, not a physical
  fire-spread model.
- No comparison against the paper's own reported numerical results is made
  or implied — the objectives, environment, and vehicle count differ, so
  such a comparison would not be meaningful without re-implementing the
  paper's exact multi-UAV setup.

## Precise implementation status

**IMPLEMENTED:**
- Single-UAV NSGA-II mission optimization
- Permutation-based mission representation (confirmed genuine feasible
  subset selection, not just ordering — see tests above)
- ConvLSTM checkpoint integration (pipeline wiring, functional end-to-end)
- Prediction-to-target conversion, with P(fire) and expected-damage kept as
  separate quantities
- D* Lite path planning, including genuine incremental replanning actually
  used by the execution path (not merely implemented and unreferenced)
- Online replanning, end-to-end, with per-tick state recording and
  animation
- Optional risk-weighted D* Lite routing (off by default)

**NOT CLAIMED:**
- Accurate real-world ConvLSTM predictions (checkpoint is synthetic-trained
  only; a real NASA FIRMS test found it performs worse than a do-nothing
  baseline — see caveat above)
- Physical wildfire damage modeling (the expected-damage-proxy is a
  documented multiplicative heuristic, not a validated model)
- Physically accurate fire-risk traversal costs (same caveat — a
  configurable proxy, explicitly labeled as such)
- Reproduction of Zhu et al.'s exact numerical results (different
  objectives, environment, and vehicle count — see Limitations)
- Multi-UAV optimization (not attempted)

**Module separation preserved** (verified by inspection — no cross-imports
found): `PredictionSource` implementations do not know how NSGA-II or D*
Lite work; NSGA-II (`mission/optimizer/nsga2.py`) and D* Lite
(`mission/optimizer/dstar_lite.py`) do not import anything ConvLSTM-specific
— the only ConvLSTM/torch dependency in the whole `mission/` package lives
in `mission/simulation/prediction_source.py`, the designated bridge module.
